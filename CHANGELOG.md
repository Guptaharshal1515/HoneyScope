# Changelog

## [Unreleased]
### Added
- **Scenario `llm-chatbot`** (CWE-200, LLM01:2025, T1589.002): LLM prompt injection and sensitive data disclosure via `/api/chat`. Offline rule-based mock model. Four levels: `low` (direct prompt injection overrides constraints, leaking system prompt and override token `OVERRIDE-7749`), `medium` (keyword blocklist bypassed via maintenance/debug roleplay persona), `high` (input filter + exact output filter bypassed via character delimiting/spacing), `impossible` (secrets decoupled from prompt context, dual guardrails, output DLP). Wazuh rules 100524–100525, Sigma rule, `attack.py`, 20 tests. Containment verified.
- **Scenario `race-condition`** (CWE-362, T1499): Concurrency and business logic flaws via `/api/coupon/apply`. Four levels: `low` (unprotected TOCTOU gap allows double redemption), `medium` (lock around balance update only, leaving validation check unsynchronized), `high` (per-request Lock instantiation fails mutual exclusion across threads), `impossible` (shared critical section protecting check and update). Wazuh rules 100522–100523, Sigma rule, `attack.py`, 17 tests.
- **Scenario `cmd-inject`** (CWE-78/CWE-22/CWE-611, T1059.004): Command injection (`/api/cmd`), path traversal (`/api/file`), and XXE (`/api/xml`). Four levels: `low` (unfiltered separators, path traversal, SYSTEM entities), `medium` (filters `;`/`&&`, single-pass replace `../`, case-sensitive `SYSTEM`), `high` (unanchored regex prefix, absolute file paths, internal parameter entities), `impossible` (strict IP regex, basename allowlist, entity expansion disabled). Pure in-memory virtual filesystem and mock command interpreter. Wazuh rules 100520–100521, Sigma rule, `attack.py`, 26 tests. Containment verified.
- **Scenario `insecure-deserialise`** (CWE-502, T1059): Deserialization vulnerabilities via `/api/deserialise`. Four levels: `low` (simulated pickle gadget opcode stream), `medium` (JSON custom class instantiator with blocklist against direct OS calls, allowing `DiagnosticGadget`), `high` (class allowlist with naive `startswith('SafeConfig')`), `impossible` (strict primitive schema parsing, dynamic instantiation removed). Pure simulation: no native deserializer or code execution. Wazuh rules 100518–100519, Sigma rule, `attack.py`, 20 tests. Containment verified.
- **Scenario `file-upload`** (CWE-434, T1105): Insecure file upload flaws via `/api/upload`. Four levels: `low` (unrestricted uploads), `medium` (Content-Type header validation only; spoofable), `high` (extension allowlist on last dot + Content-Type; double extensions like `.php.jpg` pass), `impossible` (extension allowlist + Content-Type + magic byte verification + UUID filename). Files stored in sandbox, served with `Content-Disposition: attachment`, never executed. Wazuh rules 100514–100515, Sigma rule, `attack.py`, 23 tests. Containment verified.
- **Scenario `graphql-abuse`** (CWE-284, T1190): GraphQL vulnerabilities via `/api/graphql`. Four levels: `low` (introspection enabled, unbounded depth, unlimited batching, `adminData` accessible), `medium` (introspection disabled and sensitive field blocked; batching array abuse allowed), `high` (depth limited to 5 and batching capped at 2; field alias amplification >3 allowed), `impossible` (depth <= 3, batching disabled, aliases <= 3, introspection disabled). Wazuh rules 100516–100517, Sigma rule, `attack.py`, 26 tests.
- **Scenario `api-auth`** (CWE-284, T1548): Broken API object-level and function-level authorization via `/api/users/` and `/api/admin/`. Four levels: `low` (BOLA on GET/POST + unrestricted admin endpoint), `medium` (GET checks ownership; POST trusts form `user_id`; `?role=admin` query param bypass), `high` (ownership enforced; user listing leaks salary; `X-Role: admin` header trusted), `impossible` (strict session ownership, public fields only, server-side role check). Wazuh rules 100512–100513, Sigma rule, `attack.py`, 31 tests.
- **Scenario `ssrf`** (CWE-918, T1090): Server-Side Request Forgery via `/api/fetch` and mock internal services (`http://internal-metadata/`, `http://internal-api/`). Four levels: `low` (any URL accepted), `medium` (blacklist blocks exact strings like `169.254.169.254`; internal DNS name bypasses), `high` (allowlist enforced but follows open redirects), `impossible` (allowlist + HTTPS only + redirects disabled). In-memory fake internal services; no real external network requests. Wazuh rules 100510–100511, Sigma rule, `attack.py`, 33 tests. Containment verified.
- **Scenario `jwt-flaws`** (CWE-347, T1550.001): JWT handling flaws via `/api/auth/login` + `/api/auth/profile`. Four levels: `low` (alg=none accepted — unsigned tokens trusted), `medium` (alg=none blocked but HMAC secret is `"secret"` — crackable offline), `high` (strong secret + alg=none blocked; `kid` header accepted and used for key lookup — `kid=dev` → known weak `dev-secret`), `impossible` (algorithm pinned in code, `kid` ignored, strong env-var secret). Flask Blueprint `lab_api` added for all Phase-2 API scenarios. `PyJWT==2.*` added to `requirements.txt`. Wazuh rules 100508–100509, Sigma rule, `attack.py`, 35 tests. Flags in lab mode; containment verified.
- **Scenario `weak-creds`** (CWE-798, T1078.001): Weak/default credentials on the management login panel (`/mgmt` → `/admin`). Four levels: `low` (hardcoded `admin/admin123`, plain `==`, no rate limit — original honeypot behaviour), `medium` (password in env var `HONEYSCOPE_ADMIN_PASS`, default still `admin123`, no rate limit), `high` (env-var password + 5-failures/60 s per-IP in-process rate limiter; bypassable via different IP or server restart), `impossible` (`secrets.compare_digest` + rate limiter; env var must be set to a strong secret). Wazuh rules 100506–100507, Sigma rule, `attack.py` replay script, 30 tests. Flags work in lab mode; containment verified.
- **Scenario `idor-profile`** (CWE-639/CWE-862, T1078): IDOR + privilege escalation on the profile page. Four levels: `low` (no ownership check, role editable), `medium` (GET checks ownership; POST trusts form `user_id`), `high` (ownership fixed; role still editable by any user on own profile), `impossible` (ownership enforced; role ignored from form). Wazuh rules 100504–100505, Sigma rule, `attack.py` replay script, 37 tests. Flags work in lab mode; containment verified.
- **Scenario `xss-stored`** (CWE-79, T1059.007): Stored XSS on the employee feedback form (`/submit_comment`). Four levels: `low` (verbatim storage with `| safe`), `medium` (strips `<script>` only), `high` (named-tag blocklist, single-pass), `impossible` (`html.escape()` at write time — the reference fix). Wazuh rules 100502–100503, Sigma rule, `attack.py` replay script, 30 tests. Flags work in lab mode; containment verified. Existing honeypot behaviour at `low` is preserved.
- **Scenario generator** `Website/tools/new_scenario.py`: creates a draft scenario skeleton (metadata, level stubs, README outline, Wazuh + Sigma templates with auto-allocated rule IDs, replay-script stub, skeleton tests). Writes no exploit code or payloads.
- `"status": "draft"` in `scenario.json` hides a scenario from `/lab` and the scoreboard; `load_scenarios()` takes `base` and `include_drafts`.
- 8 more tests (53 total).
- **Flags and scoreboard** (lab mode only): HMAC-derived flag per scenario and level, shown on the dashboard after a real login bypass; submit on `/lab` to tick the scoreboard. `HONEYSCOPE_FLAG_SECRET` sets the secret. No flag at `impossible`.
- 12 more tests (45 total).
- **Lab index page** at `/lab` (opt-in with `HONEYSCOPE_LAB=1`, 404 otherwise): lists scenarios, shows per-level hints (no solutions), and switches difficulty at runtime.
- `scenarios.load_scenarios()`, `set_level()` and `lab_enabled()` helpers; runtime level override beats `HONEYSCOPE_LEVEL`.
- `hints` and `target` fields in `scenario.json`.
- 10 more tests (33 total) covering the lab page, hidden-by-default behaviour, level switching and `scenario.json` schema.

## [0.2.0-lab] - 2026-11-14
### Added
- Open-source project files: LICENSE (MIT), CONTRIBUTING, CODE_OF_CONDUCT, SECURITY, ROADMAP, issue/PR templates.
- **Lab mode:** difficulty levels via `HONEYSCOPE_LEVEL` (`low` | `medium` | `high` | `impossible`).
- First scenario, `sqli-login`: four levels, write-up, Wazuh rules (IDs 100500-100501), Sigma rule, and `attack.py` replay script.
- pytest suite (23 tests at the time) and GitHub Actions CI (tests on Python 3.11/3.12 + Docker build).
- `lab_level` field in every access-log entry.
- `.env.example`, `requirements-dev.txt`.

### Changed
- Flask debug mode is now opt-in (`HONEYSCOPE_DEBUG=1`); it previously ran with the Werkzeug debugger on `0.0.0.0`.
- `low` level no longer accepts a wrong password for a valid username; the username-only fallback now only runs when the username contains a quote (the original injection quirk is preserved).
- README restructured around honeypot and lab modes; fixed clone path.

### Fixed
- Removed obsolete `version:` key from `docker-compose.yml`.
